개발, 스테이징, 프로덕션을 분리해야 한다면 **환경마다 자체 호스팅 Sigiro 인스턴스와 데이터 디렉터리를 하나씩** 사용하세요. OTLP 및 쿼리 리스너, 네트워크 경계의 자격 증명, 저장소 및 백업 접근 권한, 보존 설정도 분리하세요. 각 환경의 익스포터는 해당 환경의 OTLP 엔드포인트로만 보내야 합니다. 포트만 다르게 설정하고 데이터 디렉터리나 저장소 백엔드를 공유하면 격리되지 않습니다.

로컬 바이너리를 사용할 때는 `sigiro serve` 프로세스마다 별도의 디렉터리와 세 리스너 포트를 지정합니다. 아래는 개발 전용 호스트의 예입니다.

```bash
SIGIRO_RETENTION_DAYS=2 sigiro serve \
  --data-dir /srv/sigiro/dev \
  --http-port 19999 --otlp-http-port 14318 --otlp-grpc-port 14317
```

스테이징과 프로덕션은 **별도 프로세스**, 별도 경로, 겹치지 않는 포트로 운영하고 가능하면 호스트나 네트워크 구간도 분리하세요. 이 예시는 TLS나 인증을 구성하지 않습니다. 신뢰할 수 없는 네트워크에 리스너를 노출하지 마세요. 프로덕션 텔레메트리, 백업, 저장소 자격 증명은 프로덕션 보안 경계 안에 보관하세요. 환경마다 `SIGIRO_RETENTION_DAYS`를 별도로 설정하세요. 디렉터리를 삭제하는 것은 보존 정책이 아닙니다. 컨테이너 볼륨과 localhost 전용 포트 매핑은 [자체 호스팅 빠른 시작](/docs/tutorials/quickstart), 설정은 [CLI 참고](/docs/reference/cli)를 확인하세요.

## 공유 인스턴스가 격리하지 못하는 것

Open 모드에서는 Sigiro가 인증 없이 요청을 받고 합성된 `default` 테넌트로 처리합니다. `default`는 **환경 경계가 아닙니다**. 개발과 프로덕션 요청을 같은 Open 모드 인스턴스로 보내면 테넌트와 쿼리 대상을 공유합니다. 프로덕션과 신뢰도가 낮은 트래픽을 공유 Open 엔드포인트에 보내지 마세요. 이 문서는 테스트되지 않은 인증된 테넌트 간 동작을 보장하지 않습니다.

`deployment.environment`는 OpenTelemetry **리소스 속성**이지 Sigiro 프로젝트 ID나 권한 부여 규칙이 아닙니다. 의도적으로 공유한 인스턴스에서는 레이블로 쿼리를 필터링할 수 있지만 레이블의 누락, 오타, 발신자가 임의로 지정한 값으로 데이터가 섞이거나 빠질 수 있습니다. 내장 진단 및 다른 쿼리에 이 SQL 필터가 자동으로 적용되지는 않습니다. 익스포터가 각 스팬의 리소스에 `deployment.environment=staging`을 설정한 뒤, 다음 리터럴 SQL을 인스턴스의 `/v1/query`에 전송할 수 있습니다.

```sql
SELECT service_name, count(*) AS span_count
FROM sigiro_spans
WHERE timestamp >= TIMESTAMP '2026-09-23 00:00:00'
  AND timestamp < TIMESTAMP '2026-09-24 00:00:00'
  AND (resource_attributes::JSON->>'deployment.environment') = 'staging'
GROUP BY service_name
ORDER BY span_count DESC;
```

두 시간을 원하는 유한한 반개구간으로 바꾸세요. 값은 `sigiro_spans.resource_attributes`에 저장된 JSON 문자열에서 읽으며 별도의 스키마 열이 아닙니다. 이 필터는 **쿼리 관례**일 뿐 접근 제어, 저장소 격리 또는 별도 인스턴스를 대체하지 못합니다.

## 트레이드오프

저장소와 네트워크 접근도 분리한다면 별도 인스턴스의 Open 모드 쿼리 엔드포인트는 다른 환경의 데이터를 읽지 못합니다. 대신 개발, 스테이징, 프로덕션을 한 번의 로컬 쿼리로 조회할 수 없습니다. 비교하려면 각 엔드포인트를 따로 조회하고 권한이 부여된 외부 작업에서 결과를 합치세요. 그 작업에 환경별 접근 권한을 명시적으로 부여하세요. 공유 인스턴스는 환경 간 SQL 조회가 쉽지만 분리를 포기하고 필터링 책임을 운영자에게 맡깁니다. 원격 OTLP 및 쿼리 접근은 TLS와 접근 제어가 있는 진입점이나 신뢰할 수 있는 사설망으로 보호하세요. 공개된 평문 연결로 자격 증명이나 텔레메트리를 보내지 마세요. 진입점, 익스포터, 저장소 자격 증명을 환경마다 별도로 관리하고 교체하세요.
