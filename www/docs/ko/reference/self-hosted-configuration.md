이 문서는 현재 `src/config.rs`에 정의된 설정을 설명합니다. 환경 변수는 `sigiro serve`를 **시작하기 전에** 설정하십시오. 서버 설정을 변경하려면 재시작해야 합니다. 요청 시 읽히는 비밀 값도 핫 리로드가 지원되지 않으므로 마찬가지입니다. 클라이언트 설정은 CLI가 읽으므로 변경 후 클라이언트 명령을 다시 실행하십시오. 별도 언급이 없는 한 아래의 숫자형 값은 부호 없는 정수입니다. 기본값이 ‘설정되지 않음’으로 표시된 항목에서 빈 값은 **미설정 값과 다릅니다**. `serve` 플래그로 지정할 수 있는 설정은 네 가지뿐이며, 나머지 서버 설정은 환경 변수로만 지정할 수 있습니다.

## 서버 리스너, 스토리지 및 보안

| 변수                                                                 | 기본값, 유효한 값 및 동작                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SIGIRO_DATA_DIR`                                                    | 플랫폼별 데이터 디렉터리(Unix에서는 `~/.local/share/sigiro`); 파일 시스템 경로. `--data-dir`로 재지정할 수 있습니다. Docker에서는 이 볼륨을 영속화하십시오.                                                                                                                              |
| `SIGIRO_HTTP_PORT`                                                   | `9999`; TCP 포트(0–65535, 단 `0`은 OS가 포트를 할당하도록 합니다). `--http-port`로 재지정할 수 있습니다. 네이티브 OTLP TLS를 사용해도 기본 API는 **평문**입니다.                                                                                                                         |
| `SIGIRO_GRPC_PORT`                                                   | `4317`; TCP 포트. `--otlp-grpc-port`로 재지정할 수 있습니다.                                                                                                                                                                                                                             |
| `SIGIRO_OTLP_HTTP_PORT`                                              | `4318`; TCP 포트. `--otlp-http-port`로 재지정할 수 있습니다.                                                                                                                                                                                                                             |
| `SIGIRO_TLS_CERT`, `SIGIRO_TLS_KEY`                                  | 둘 다 미설정이면 OTLP는 평문입니다. OTLP gRPC와 OTLP HTTP에 TLS를 적용하려면 **두 변수 모두** 읽을 수 있는 PEM 인증서 체인 파일 및 개인 키 파일의 경로로 설정하십시오. 한쪽이 없거나 파일이 유효하지 않거나 읽을 수 없으면 시작에 실패합니다. mTLS는 지원하지 않습니다.                  |
| `SIGIRO_AUTH_ISSUER`, `SIGIRO_AUTH_AUDIENCE`, `SIGIRO_AUTH_JWKS_URL` | 세 값이 모두 비어 있으면 **Open** 모드로, 요청별 인증을 하지 않습니다. JWT 리소스 서버 검증을 사용하려면 세 값을 모두 설정해야 하며, 일부만 설정하면 실패합니다. 분산 모드에는 JWT가 필요합니다. **단순한 고정 bearer 토큰 모드는 없습니다**. TLS를 켠다고 인증이 활성화되지는 않습니다. |
| `SIGIRO_ADMIN_TOKEN`                                                 | 미설정이면 분산 환경의 테넌트/키 프로비저닝 변경 엔드포인트가 비활성화됩니다. 설정하면 관리자용 bearer 비밀 값으로 사용되며, **일반적인 수집/쿼리 토큰이 아닙니다**.                                                                                                                     |
| `SIGIRO_CATALOG_URL`                                                 | 미설정이면 로컬 DuckLake 파일 카탈로그를 사용합니다. PostgreSQL `postgres://` 또는 `postgresql://` URL을 설정하면 분산 카탈로그를 사용합니다. 명시적으로 빈 값을 설정하면 유효하지 않습니다. 자격 증명을 비밀로 취급하십시오.                                                            |
| `SIGIRO_S3_BUCKET`, `SIGIRO_S3_REGION`, `SIGIRO_S3_ENDPOINT`         | 값이 비어 있으면 S3를 사용하지 않습니다. S3 스토리지를 사용하려면 PostgreSQL 카탈로그와 함께 버킷 및 리전을 설정하십시오. S3 호환 스토어에는 절대 HTTP(S) origin 엔드포인트가 필요하며 경로, 쿼리 및 자격 증명을 포함해서는 안 됩니다.                                                   |
| `SIGIRO_S3_KEY_ID`, `SIGIRO_S3_SECRET`                               | 값이 비어 있으면 각각 `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`를 대신 사용합니다. S3 버킷을 설정했다면 필수입니다. 비밀 값이 로그나 셸 기록에 남지 않게 하십시오.                                                                                                                    |
| `SIGIRO_EXTENSION_DIR`                                               | 값이 비어 있으면 데이터 디렉터리 아래의 확장 기능 캐시를 사용합니다. 설정할 경우 쓰기 가능하거나 확장 기능이 미리 배치된 DuckDB 확장 기능 디렉터리의 파일 시스템 경로를 지정하십시오.                                                                                                    |
| `SIGIRO_ALLOW_UNSIGNED_EXTENSIONS`                                   | `false`; 불리언 값. `true`이면 서명되지 않은 로컬 DuckDB 확장 기능을 허용합니다. 신뢰할 수 없는 파일에 대해서는 활성화하지 마십시오.                                                                                                                                                     |
| `SIGIRO_HOSTED_DATA_DIR`, `SIGIRO_DUCKDB_CACHE_DIR`                  | 호스팅 모드의 파일 시스템 경로로, 기본값은 각각 `/var/lib/sigiro/telemetry`와 `/var/cache/sigiro/duckdb`입니다. 일반적인 자체 호스팅 데이터 디렉터리가 아닙니다.                                                                                                                         |
| `SIGIRO_OTEL_AUTH_KEY`                                               | 빈 값; Sigiro **자체 텔레메트리 내보내기**의 자격 증명이며 서버 요청 인증에는 사용되지 않습니다.                                                                                                                                                                                         |
| `SIGIRO_ALERT_WEBHOOK_URL`, `SIGIRO_ALERT_WEBHOOK_TOKEN`             | URL이 비어 있으면 웹훅 전송이 비활성화됩니다. 선택적 토큰은 발신 경고 웹훅 요청을 인증하며, 수신 OTLP/API 호출을 인증하지 않습니다.                                                                                                                                                      |
| `SIGIRO_PYROSCOPE_ENDPOINT`                                          | 값이 비어 있으면 프로파일링 내보내기가 비활성화됩니다. 그 외에는 Pyroscope 엔드포인트 URL을 지정합니다.                                                                                                                                                                                  |

## 수집, 보존 기간 및 쿼리 제한

| 변수                                                           | 기본값, 유효한 값 및 동작                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SIGIRO_RETENTION_DAYS`                                        | `7`일; 부호 없는 32비트 정수이며 `0`은 자동 보존을 비활성화합니다. 매시간 실행되는 정리 작업이 기록 노드의 신호 테이블에서 타임스탬프가 오래된 텔레메트리 행을 삭제합니다. 이후 DuckLake 체크포인트/스냅샷 만료를 통해 실제 파일 공간을 회수합니다(`DELETE`만으로는 바이트가 해제되지 않을 수 있습니다). 파생 데이터와 관리 데이터에 이 보존 기한이 적용된다고 보장하지 않습니다.                                                                                            |
| `SIGIRO_MAX_DISK_BYTES`                                        | `0`(비활성화); 부호 없는 64비트 정수로 지정하는 원시 바이트 수입니다. 주기적으로 측정하는 **로컬** 데이터 디렉터리의 소프트 한도입니다. 사용량이 한도 이상이면 새 수집을 HTTP **507** 또는 gRPC **resource_exhausted**로 거부합니다. 이후 측정값이 한도의 **90% 미만**이면 수집을 재개합니다. 대기열에 있거나 처리 중인 데이터로 한도를 초과할 수 있으므로 디스크 여유 공간을 남겨 두십시오. S3 Parquet 및 외부 PostgreSQL 카탈로그의 바이트는 **계산에 포함되지 않습니다**. |
| `SIGIRO_DISK_SAMPLE_SECONDS`                                   | `30`초; 0보다 큰 부호 없는 64비트 정수입니다. 보존 정책이나 디스크 한도가 활성화된 경우에만 측정합니다. 한도에 도달하면 보존 정책이 활성화된 경우 중복 실행되지 않는 보존 정리 작업을 시작하며, 다음 측정 결과에 따라 복구 여부를 결정합니다.                                                                                                                                                                                                                                |
| `SIGIRO_MAX_CHECKPOINT_FAILURES`                               | 프로젝트별 연속 실패 `3`회; 부호 없는 32비트 정수입니다. 임계값에 도달하면 해당 프로젝트의 수집을 HTTP 507 / gRPC resource_exhausted로 차단하고 상태가 저하되었다고 보고합니다. 체크포인트가 성공하면 실패 횟수를 초기화하고 수집을 다시 활성화합니다. `0`은 수집 차단만 비활성화하며 **실패 보고는 비활성화하지 않습니다**. 특히 PostgreSQL 카탈로그가 로컬 디스크 측정 대상 밖에서 커지는 경우 중요합니다.                                                                 |
| `SIGIRO_MAX_INGEST_BODY_BYTES`                                 | `8388608`바이트(8 MiB); 양의 정수입니다. 디코딩된 gRPC 메시지 및 압축 해제된 OTLP HTTP 본문의 최대 크기입니다.                                                                                                                                                                                                                                                                                                                                                               |
| `SIGIRO_BACKPRESSURE_POLICY`                                   | 기본값 `block`; `block` 또는 `drop-newest`를 지정합니다. `block`은 프로젝트별 크기가 제한된 큐에 공간이 생길 때까지 기다리므로 클라이언트가 느려질 수 있습니다. `drop-newest`는 큐가 가득 차면 새 메시지를 버리고 데이터 손실을 기록하지만 **성공을 반환합니다**(429가 아님). 어느 정책도 영속 버퍼링을 제공하지 않으므로 장애에 대비해 컬렉터의 전송 큐와 재시도를 설정하십시오.                                                                                            |
| `SIGIRO_FLUSH_INTERVAL_SECS`                                   | `1`초; 부호 없는 64비트 정수로 지정하는 주기입니다. 버퍼에 쌓인 행을 플러시하는 타이머이며, 행/바이트 임계값에 도달하면 더 일찍 플러시할 수 있습니다.                                                                                                                                                                                                                                                                                                                        |
| `SIGIRO_FLUSH_ROW_THRESHOLD`                                   | `10000`행; 부호 없는 정수이며 프로젝트별 신호 테이블 전체에 적용됩니다.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `SIGIRO_FLUSH_BYTE_THRESHOLD`                                  | `8388608`바이트(8 MiB); 부호 없는 정수이며 프로젝트별 버퍼에 적용됩니다.                                                                                                                                                                                                                                                                                                                                                                                                     |
| `SIGIRO_SHUTDOWN_TIMEOUT_SECS`                                 | 프로젝트별 대기열 비우기에 `5`초; 0보다 큰 부호 없는 64비트 정수입니다. 스토리지가 느리면 이 시간을 초과하여 버퍼의 데이터가 플러시되지 않을 수 있습니다.                                                                                                                                                                                                                                                                                                                    |
| `SIGIRO_DUCKDB_THREADS`                                        | 호스트에서 사용 가능한 병렬 처리 수준; 양의 정수이며 프로젝트별 데이터베이스에서 사용할 DuckDB 스레드 수입니다.                                                                                                                                                                                                                                                                                                                                                              |
| `SIGIRO_DUCKDB_MEMORY_LIMIT`                                   | `400MB`; 비어 있지 않은 DuckDB 메모리 크기 문자열(예: `8GB`)이며 프로젝트별 데이터베이스에 적용됩니다. 진단/쿼리 시 메모리가 부족하면 가용 RAM에 맞춰 늘리십시오.                                                                                                                                                                                                                                                                                                            |
| `SIGIRO_QUERY_TIMEOUT_SECONDS`                                 | `30`초; 0보다 큰 부호 없는 64비트 정수이며 쿼리별 감시 타이머의 제한 시간입니다.                                                                                                                                                                                                                                                                                                                                                                                             |
| `SIGIRO_MAX_RESULT_ROWS`                                       | `100000`행; 양의 정수이며 `/v1/query` 응답을 잘라 내기 전 최대 행 수입니다.                                                                                                                                                                                                                                                                                                                                                                                                  |
| `SIGIRO_QUERY_ROW_CAP`                                         | `1000000`행; 양의 정수이며 페더레이션 쿼리에서 엣지별 부분 결과의 최대 행 수입니다.                                                                                                                                                                                                                                                                                                                                                                                          |
| `SIGIRO_QUERY_SURFACE`                                         | 기본값 `none`; `none` 또는 `quack`을 지정합니다. `quack`은 엣지에서 프로젝트 간 DuckDB 쿼리 서비스를 노출합니다.                                                                                                                                                                                                                                                                                                                                                             |
| `SIGIRO_QUACK_BIND`, `SIGIRO_QUACK_PORT`, `SIGIRO_QUACK_TOKEN` | 각각 `127.0.0.1`, `7777`, 빈 토큰. 바인드 주소는 IP 주소여야 하며 포트는 TCP 포트입니다. 토큰은 **quack 인터페이스 전용**으로 OTLP/기본 API에는 사용되지 않습니다. 평문 quack 인터페이스를 신뢰할 수 없는 네트워크에 노출하지 마십시오.                                                                                                                                                                                                                                      |

플러시 행/바이트 임계값에는 부호 없는 자료형이라는 조건 외에 공통으로 적용되는 최솟값이 없습니다. 이 설정에서 `0`은 **비활성화 값으로 문서화되어 있지 않습니다**. 자료형에 맞는 값도 내부 하위 시스템에서 거부될 수 있습니다. 표에 명시적인 비활성화 값이 없는 설정에는 지원되는 비활성화 관례가 없습니다.

| `OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_ENDPOINT` | 각각 `sigiro`, 빈 값; Sigiro 자체 계측의 서비스 이름과 내보내기 엔드포인트입니다. `SIGIRO_*` 변수는 아니지만 `src/config.rs`에 정의되어 있습니다.                       |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`       | 빈 값; 대응하는 `SIGIRO_S3_*` 값이 비어 있을 때 대체로 사용하는 S3 자격 증명입니다.                                                                                     |

## Docker: 직접 OTLP 수집에 TLS 적용

클라이언트가 사용하는 호스트 이름과 일치하는 SAN이 포함된 자체 인증서를 사용하십시오. 다음 예시는 OTLP 포트만 호스트에 노출하고 평문 기본 API는 루프백에서만 접근할 수 있도록 합니다. 이미지 태그와 데이터 볼륨은 배포 환경에 맞게 조정하십시오.

```sh
docker run --name sigiro \
  -v sigiro-data:/var/lib/sigiro \
  -v "$PWD/certs:/certs:ro" \
  -e SIGIRO_TLS_CERT=/certs/server.pem \
  -e SIGIRO_TLS_KEY=/certs/server-key.pem \
  -p 127.0.0.1:9999:9999 -p 4317:4317 -p 4318:4318 \
  ghcr.io/sigiroai/sigiro:latest serve
```

gRPC 내보내기의 주소는 `https://your-host:4317`, OTLP HTTP 내보내기의 주소는 `https://your-host:4318`로 설정하십시오. HTTP 엔드포인트를 명시적으로 지정할 때는 `/v1/traces`와 같은 신호 경로를 사용하십시오. 클라이언트는 서명 CA를 신뢰하거나 자체 서명 인증서를 명시적으로 신뢰해야 하며, 일치하는 DNS SAN도 검증해야 합니다. 인증서 검증을 **비활성화하지 마십시오**. `9999`의 기본 API는 호스트 내에서 계속 `http://`를 사용하므로 원격 쿼리/API 클라이언트에 대한 HTTPS는 리버스 프록시에서 종료하십시오. TLS는 전송을 보호할 뿐 **접근을 제어하지 않습니다**. Open 모드에서는 리스너에 도달하는 모든 요청을 여전히 허용합니다. JWT 설정 세 가지를 모두 구성하거나 신뢰할 수 있는 네트워크 뒤에 포트를 격리하십시오. `tests/grpc_tls_test.rs`에서는 실제 서버의 TLS gRPC 통신 경로, TLS HTTP 핸드셰이크 및 평문 기본 API를 검증합니다. 위 Docker 명령과 이미지 태그 자체는 별도로 통합 테스트되지 않았습니다.
