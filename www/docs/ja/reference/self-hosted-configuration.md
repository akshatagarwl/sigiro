このリファレンスでは、現在の `src/config.rs` で扱う設定を説明します。環境変数は `sigiro serve` を**起動する前**に設定してください。サーバー設定を変更した場合は再起動が必要です（リクエスト時に読み取られるシークレットも、ホットリロードの手段としてはサポートされていません）。クライアント設定は CLI が読み取るため、変更後はクライアントコマンドを再実行してください。特に断りがなければ、以下の数値型は符号なし整数です。「未設定」と記載した項目では、空文字列は**未設定と同じではありません**。`serve` のフラグがある設定は 4 つだけです。その他のサーバー設定は環境変数でのみ指定できます。

## サーバーのリスナー・ストレージ・セキュリティ

| 変数                                                                 | デフォルト値・有効な値・動作                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SIGIRO_DATA_DIR`                                                    | プラットフォームのデータディレクトリ（Unix では `~/.local/share/sigiro`）。ファイルシステム上のパス。`--data-dir` で上書きできます。Docker ではこのボリュームを永続化してください。                                                                                                                                                 |
| `SIGIRO_HTTP_PORT`                                                   | `9999`。TCP ポート（0–65535。`0` は OS が割り当てるポートを選択）。`--http-port` で上書きできます。ネイティブ OTLP TLS を有効にしても、メイン API は**平文通信**です。                                                                                                                                                              |
| `SIGIRO_GRPC_PORT`                                                   | `4317`。TCP ポート。`--otlp-grpc-port` で上書きできます。                                                                                                                                                                                                                                                                           |
| `SIGIRO_OTLP_HTTP_PORT`                                              | `4318`。TCP ポート。`--otlp-http-port` で上書きできます。                                                                                                                                                                                                                                                                           |
| `SIGIRO_TLS_CERT`, `SIGIRO_TLS_KEY`                                  | 両方とも未設定なら OTLP は平文通信です。OTLP gRPC と OTLP HTTP で TLS を有効にするには、読み取り可能な PEM 形式の証明書チェーンと秘密鍵のファイルパスを**両方**設定してください。片方が欠けている場合や、ファイルが不正・読み取り不可の場合は起動に失敗します。mTLS はありません。                                                  |
| `SIGIRO_AUTH_ISSUER`, `SIGIRO_AUTH_AUDIENCE`, `SIGIRO_AUTH_JWKS_URL` | 3 つの JWT 設定と静的トークンがすべて未設定なら **Open** モードです。JWT を使う場合は 3 つすべて設定してください。一部だけなら起動失敗です。分散モードには JWT が必要です。TLS だけでは認証は有効になりません。                                                                                                                     |
| `SIGIRO_STATIC_BEARER_TOKEN`                                         | 未設定なら静的認証は無効です。ローカルのセルフホスト環境では、32 バイト以上の ASCII bearer トークンを設定するとクエリ API と両方の OTLP リスナーを保護します。JWT 設定、分散カタログ、`quack` とは併用できません。同一トークンで取り込みとクエリが可能です。[ガイド](/docs/ja/how-to/self-hosted-static-bearer)を参照してください。 |
| `SIGIRO_ADMIN_TOKEN`                                                 | 未設定なら、分散環境のテナント・キーのプロビジョニングを変更するエンドポイントは無効です。設定すると管理者用 bearer シークレットになります。**一般の取り込み・クエリ用トークンではありません**。                                                                                                                                    |
| `SIGIRO_CATALOG_URL`                                                 | 未設定ならローカルの DuckLake ファイルカタログを使用します。PostgreSQL の `postgres://` または `postgresql://` URL を指定すると分散カタログを選択します。明示的な空文字列は無効です。認証情報はシークレットとして扱ってください。                                                                                                   |
| `SIGIRO_S3_BUCKET`, `SIGIRO_S3_REGION`, `SIGIRO_S3_ENDPOINT`         | 空なら S3 を使用しません。S3 ストレージを使う場合は、PostgreSQL カタログとともにバケットとリージョンを設定してください。S3 互換ストレージには、絶対 HTTP(S) オリジンのエンドポイントが必要です（パス・クエリ・認証情報は含められません）。                                                                                          |
| `SIGIRO_S3_KEY_ID`, `SIGIRO_S3_SECRET`                               | 空なら、それぞれ `AWS_ACCESS_KEY_ID` と `AWS_SECRET_ACCESS_KEY` にフォールバックします。S3 バケットを設定した場合は必須です。シークレットをログやシェル履歴に残さないでください。                                                                                                                                                   |
| `SIGIRO_EXTENSION_DIR`                                               | 空ならデータディレクトリ配下の拡張機能キャッシュを使用します。指定する場合は、書き込み可能または拡張機能を事前配置済みの DuckDB 拡張機能ディレクトリへのファイルシステムパスです。                                                                                                                                                  |
| `SIGIRO_ALLOW_UNSIGNED_EXTENSIONS`                                   | `false`。真偽値。`true` にすると署名のないローカル DuckDB 拡張機能を許可します。信頼できないファイルには有効にしないでください。                                                                                                                                                                                                    |
| `SIGIRO_HOSTED_DATA_DIR`, `SIGIRO_DUCKDB_CACHE_DIR`                  | ホスト型モード用のファイルシステムパス。デフォルトはそれぞれ `/var/lib/sigiro/telemetry` と `/var/cache/sigiro/duckdb` です。通常のセルフホスト用データディレクトリではありません。                                                                                                                                                 |
| `SIGIRO_OTEL_AUTH_KEY`                                               | 空。Sigiro **自身のテレメトリのエクスポート**に使う認証情報であり、サーバーへのリクエストの認証には使いません。                                                                                                                                                                                                                     |
| `SIGIRO_ALERT_WEBHOOK_URL`, `SIGIRO_ALERT_WEBHOOK_TOKEN`             | URL が空なら Webhook 配信は無効です。任意のトークンは送信するアラート Webhook リクエストの認証に使い、受信する OTLP/API 呼び出しには使いません。                                                                                                                                                                                    |
| `SIGIRO_PYROSCOPE_ENDPOINT`                                          | 空ならプロファイリングのエクスポートは無効です。指定する場合は Pyroscope エンドポイント URL です。                                                                                                                                                                                                                                  |

## 取り込み・保持期間・クエリの制限

| 変数                                                           | デフォルト値・有効な値・動作                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SIGIRO_RETENTION_DAYS`                                        | `7` 日。符号なし 32 ビット整数。`0` は自動保持期間管理を無効にします。1 時間ごとのクリーンアップで、書き込み側の各シグナルテーブルからタイムスタンプ付きの古いテレメトリ行を削除します。その後、DuckLake のチェックポイントとスナップショットの期限切れ処理によって物理ファイルが回収されます（DELETE だけではディスク容量が解放されるとは限りません）。派生データや管理データにこの期限が適用される保証はありません。                                                                    |
| `SIGIRO_MAX_DISK_BYTES`                                        | `0`（無効）。符号なし 64 ビット整数で、単位はバイト。定期的にサンプリングする**ローカル**データディレクトリのソフト上限です。使用量が上限以上になると、新しい取り込みを HTTP **507** または gRPC **resource_exhausted** で拒否します。サンプリング時に使用量が**上限の 90% 未満**になったことを確認すると再開します。キュー内や処理中のデータによって上限を超過し得るため、ディスクに余裕を残してください。S3 の Parquet ファイルと外部 PostgreSQL カタログの使用量は**計上されません**。 |
| `SIGIRO_DISK_SAMPLE_SECONDS`                                   | `30` 秒。0 より大きい符号なし 64 ビット整数。保持期間管理またはディスク上限が有効な場合にのみサンプリングします。上限に達すると、保持期間管理が有効な場合は単一実行の保持期間クリーンアップが起動し、次回のサンプリングで復旧を判定します。                                                                                                                                                                                                                                               |
| `SIGIRO_MAX_CHECKPOINT_FAILURES`                               | プロジェクトごとに連続 `3` 回の失敗。符号なし 32 ビット整数。しきい値に達すると、そのプロジェクトの取り込みを HTTP 507 / gRPC resource_exhausted で拒否し、ヘルス状態の悪化を報告します。チェックポイントが成功するとカウンターをリセットし、取り込みを再開します。`0` は取り込み拒否を無効にしますが、**失敗の報告は無効にしません**。PostgreSQL カタログがローカルディスクのサンプリング対象外で肥大化する場合に特に重要です。                                                          |
| `SIGIRO_MAX_INGEST_BODY_BYTES`                                 | `8388608` バイト（8 MiB）。正の整数。デコード後の gRPC メッセージと、展開後の OTLP HTTP 本文の最大サイズです。                                                                                                                                                                                                                                                                                                                                                                            |
| `SIGIRO_BACKPRESSURE_POLICY`                                   | デフォルトは `block`。選択肢は `block` または `drop-newest`。`block` はプロジェクトごとの容量に上限があるキューに空きができるまで待機し、クライアントを遅くする場合があります。`drop-newest` はキューが満杯になると新しいメッセージを破棄し、データ損失をログに記録したうえで**成功を返します**（429 ではありません）。どちらも永続的なバッファリングは提供しません。障害に備えてコレクターの送信キューとリトライを設定してください。                                                     |
| `SIGIRO_FLUSH_INTERVAL_SECS`                                   | `1` 秒。符号なし 64 ビット整数の間隔。バッファリングした行をフラッシュするタイマーです。行数・バイト数のしきい値により、さらに早くフラッシュされる場合があります。                                                                                                                                                                                                                                                                                                                        |
| `SIGIRO_FLUSH_ROW_THRESHOLD`                                   | `10000` 行。符号なし整数。プロジェクトごとに各シグナルテーブルを通算した行数です。                                                                                                                                                                                                                                                                                                                                                                                                        |
| `SIGIRO_FLUSH_BYTE_THRESHOLD`                                  | `8388608` バイト（8 MiB）。符号なし整数。プロジェクトごとにバッファリングしたデータ量です。                                                                                                                                                                                                                                                                                                                                                                                               |
| `SIGIRO_SHUTDOWN_TIMEOUT_SECS`                                 | プロジェクトごとの排出処理に `5` 秒。0 より大きい符号なし 64 ビット整数。ストレージの処理が遅いとこの時間を超え、バッファ内のデータがフラッシュされないまま残る場合があります。                                                                                                                                                                                                                                                                                                           |
| `SIGIRO_DUCKDB_THREADS`                                        | ホストで利用可能な並列度。正の整数。プロジェクトのデータベースごとの DuckDB スレッド数です。                                                                                                                                                                                                                                                                                                                                                                                              |
| `SIGIRO_DUCKDB_MEMORY_LIMIT`                                   | `400MB`。空ではない DuckDB のメモリサイズ文字列（例: `8GB`）。プロジェクトのデータベースごとに適用されます。診断やクエリでメモリが不足する場合は、利用可能な RAM に応じて増やしてください。                                                                                                                                                                                                                                                                                               |
| `SIGIRO_QUERY_TIMEOUT_SECONDS`                                 | `30` 秒。0 より大きい符号なし 64 ビット整数。クエリごとのウォッチドッグタイムアウトです。                                                                                                                                                                                                                                                                                                                                                                                                 |
| `SIGIRO_MAX_RESULT_ROWS`                                       | `100000` 行。正の整数。切り詰める前の `/v1/query` 応答の最大行数です。                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `SIGIRO_QUERY_ROW_CAP`                                         | `1000000` 行。正の整数。フェデレーションクエリにおけるエッジごとの部分結果の行数上限です。                                                                                                                                                                                                                                                                                                                                                                                                |
| `SIGIRO_QUERY_SURFACE`                                         | デフォルトは `none`。選択肢は `none` または `quack`。`quack` はエッジ上でプロジェクト横断の DuckDB クエリ提供機能を公開します。                                                                                                                                                                                                                                                                                                                                                           |
| `SIGIRO_QUACK_BIND`, `SIGIRO_QUACK_PORT`, `SIGIRO_QUACK_TOKEN` | それぞれ `127.0.0.1`、`7777`、空のトークン。バインド先は IP アドレスでなければならず、ポートは TCP です。トークンは **quack の提供機能だけ**に使い、OTLP やメイン API には使いません。平文通信の quack を信頼できないネットワークに公開しないでください。                                                                                                                                                                                                                                 |

フラッシュの行数・バイト数のしきい値には、符号なし型であること以外に共通の最小値はありません。これらの設定では、`0` は**無効化スイッチとして文書化されていません**。型として有効な値でも、内部のサブシステムで失敗する場合があります。表に明示的な無効化値がない設定には、サポートされる無効化の慣例はありません。

## クライアント・自己計装設定（`serve` の認証ではありません）

| 変数                                               | デフォルト値・有効な値・動作                                                                                                                                                      |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SIGIRO_ENDPOINT`                                  | 空なら localhost（`http://localhost:9999`）を選択します。ただし、OAuth ログインでホスト型環境が選択されている場合を除きます。クライアントコマンドと MCP の運用操作用の URL です。 |
| `SIGIRO_ACCESS_TOKEN`                              | 空。クライアントが送信する bearer 認証情報です。グローバルオプションの `--token <TOKEN>` で上書きできます。受信リクエストの認証は**設定しません**。                               |
| `SIGIRO_EDGES`                                     | 空なら Tailscale ピアを検出します。指定する場合は、フェデレーション `sigiro query` 用にエッジを上書きする `name=host:port` のカンマ区切りリストです。`--edge` と併用できます。    |
| `SIGIRO_DOCS_MCP_URL`                              | `https://sigiro.com/mcp/docs`。公開ドキュメントの MCP URL で、Sigiro の認証情報は転送されません。                                                                                 |
| `OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_ENDPOINT` | それぞれ `sigiro`、空。Sigiro 自身の計装のサービス名とエクスポーターのエンドポイントです。`SIGIRO_*` ではありませんが、`src/config.rs` で宣言されています。                       |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`       | 空。対応する `SIGIRO_S3_*` の値が空の場合にフォールバックとして使用する S3 認証情報です。                                                                                         |

## Docker: 直接 OTLP 取り込み時の TLS

クライアントが使用するホスト名と一致する SAN を含む独自の証明書を使用してください。この例では OTLP のポートのみをホストに公開し、平文通信のメイン API はループバックからの接続に限定します。イメージタグとデータボリュームは環境に合わせて変更してください。

```sh
docker run --name sigiro \
  -v sigiro-data:/var/lib/sigiro \
  -v "$PWD/certs:/certs:ro" \
  -e SIGIRO_TLS_CERT=/certs/server.pem \
  -e SIGIRO_TLS_KEY=/certs/server-key.pem \
  -p 127.0.0.1:9999:9999 -p 4317:4317 -p 4318:4318 \
  ghcr.io/sigiroai/sigiro:latest serve
```

gRPC エクスポーターには `https://your-host:4317`、OTLP HTTP エクスポーターには `https://your-host:4318` を設定してください（HTTP エンドポイントを明示的に指定する場合は `/v1/traces` などのシグナルごとのパスを使用します）。クライアントは署名元の CA を信頼するか、自己署名証明書を明示的に信頼し、一致する DNS SAN を検証する必要があります。証明書の検証を**無効にしないでください**。ホスト内では `9999` のメイン API は引き続き `http://` です。リモートのクエリ/API クライアント向け HTTPS はリバースプロキシで終端してください。TLS が保護するのは通信であり、**アクセスではありません**。Open モードでは、リスナーに到達できるすべてのリクエストが引き続き受け付けられます。JWT の 3 つの設定をすべて指定するか、ポートを信頼できるネットワーク内に隔離してください。`tests/grpc_tls_test.rs` では、実際のサーバーに対する TLS gRPC 通信経路、TLS HTTP ハンドシェイク、平文のメイン API をテストしています。この Docker コマンドとイメージタグ自体は、独立した統合テストでは検証されていません。
