## 1.0 前の互換性契約

**既存データディレクトリのインプレース更新は保証されません。** ローカルの
DuckLake カタログと Parquet ファイルに、リリース間で安定した形式の保証は
ありません。現時点で Sigiro 固有の保存形式バージョンも、非互換カタログを
リスナー起動前に拒否する検査もありません。起動時の `CREATE TABLE IF NOT
EXISTS` は既存テーブルを移行しません。`/health` が正常でも、古い全テーブル
との互換性の証明にはなりません。重要なデータには可変の `latest` イメージを
使わないでください。

リリースが以前の形式を読めないように変更した場合、リリースノートが
リセットを求める場合、または互換性を確認できず古いデータを開くリスクを
取れない場合には、**空のディレクトリで再開**してください。保持済みの
ローカル履歴は新環境から見えなくなります。標準の保持期間は 7 日ですが、
これは移行手段でもバックアップでもありません。サポートされた「停止して
移行する」コマンドや自動変換はありません。新しいリリースで開いたデータ
ディレクトリを旧版で使う**ダウングレードは非対応**です。旧版に戻すには、
更新前の未変更コピーと元のリリースを使います。

この手順は `SIGIRO_CATALOG_URL` を使わない**ローカル版だけ**に適用されます。
PostgreSQL カタログ、テナントのローカル Parquet、S3 のバックアップには
適用されません。

## 交換前に送信を止めてバックアップする

1. 元のイメージの正確なダイジェスト（またはバイナリのリリース）、設定、
   データディレクトリと保持期間を記録します。OTLP 送信を止めるか別の宛先
   へ切り替え、送信中の処理が終わるのを待ちます。これは運用側での停止で、
   Sigiro の移行用ドレイン API ではありません。停止中の送信には欠落が
   生じる可能性があります。
2. SIGTERM でサーバーを停止し、終了を待ちます。Sigiro はリスナーを
   停止し、書き込みタスクをドレインします。**稼働中のボリュームをコピー
   したり強制終了したりしないでください。** 終了コードとログに停止・
   ドレイン失敗がないか確認します。失敗時は最後の書き込みが保存された
   と想定しないでください。
3. 停止中にデータディレクトリ**全体**を保存します。ローカル管理情報の
   `admin.sqlite`、全プロジェクトの `catalog.ducklake` と
   `catalog.ducklake.files/`、拡張機能キャッシュを含めます。カタログだけでは
   テレメトリを復元できません。アーカイブと元のリリースを安全に保管します。

[クイックスタート](/docs/ja/tutorials/quickstart)の Docker ボリューム
`sigiro-data` を使う場合、Docker ホストで十分な空き容量を確保して実行します。

```bash
docker stop --timeout 120 sigiro
test "$(docker inspect --format '{{.State.ExitCode}}' sigiro)" = 0 # docker logs sigiro も確認
mkdir sigiro-backups # 既存のアーカイブを上書きしないよう新しい名前を選ぶ
docker run --rm \
  --mount type=volume,source=sigiro-data,target=/source,readonly \
  --mount type=bind,source="$PWD/sigiro-backups",target=/backup \
  alpine sh -c 'cd /source && tar -cf /backup/sigiro-data.tar .'
tar -tf sigiro-backups/sigiro-data.tar > /dev/null
```

終了コードが 0 でない、またはアーカイブ検査に失敗した場合は中止します。
`tar -tf` は復元可能性を保証しません。元のボリュームを残し、元のリリース
で隔離環境の復元を試してからバックアップに依存してください。バイナリ
の場合もサービスを停止して終了状態を確認し、`SIGIRO_DATA_DIR` 全体
（未指定なら通常 Unix では `~/.local/share/sigiro`）を停止中に保存します。
更新を延期するなら元のリリースを再起動します。

## 新しい空のボリュームで再開する

互換性が不明または初期化が必要な場合、元のボリュームはロールバック用に
残し、**新しい空の**ボリュームを使います。バックアップ後、Docker では:

```bash
docker rm sigiro # 停止済みコンテナのみ削除。sigiro-data は残る
if docker volume inspect sigiro-fresh >/dev/null 2>&1; then
  echo 'sigiro-fresh は既存です。別のボリューム名を選んでください' >&2
  exit 1
fi
docker volume create sigiro-fresh
IMAGE='ghcr.io/sigiroai/sigiro@sha256:REPLACE_WITH_VERIFIED_DIGEST'
docker run -d --name sigiro --restart unless-stopped \
  -p 127.0.0.1:4317:4317 -p 127.0.0.1:4318:4318 -p 127.0.0.1:9999:9999 \
  -v sigiro-fresh:/var/lib/sigiro "$IMAGE"
curl --fail http://localhost:9999/health
```

`REPLACE_WITH_VERIFIED_DIGEST` は選択した**固定の新イメージダイジェスト**に
置き換えます。旧テレメトリと管理状態は新ボリュームへ移りません。ログと
OTLP のテスト送信を確認してから送信を再開します。旧データが必要な場合、
対象リリースが**その旧版との互換性を明記しテスト済み**でない限り、新版で
開かないでください。その場合も停止時のバックアップを残し、通信再開前に
クエリと取り込みを検証してください。

## 戻す・復元する

先に新版を停止し、送信を止めます。**元の固定リリース**と**未変更の**
`sigiro-data` ボリューム、元の設定で起動し、ヘルスと実データの読み取りを
確認します。新版のボリュームに書いた内容は戻りません。元のボリュームが
失われた場合、停止時の全体アーカイブを**新しい空の**ボリュームか
ディレクトリに復元し、元のリリース・設定で起動します。バックアップに
依存する前に隔離環境で復元試験を行ってください。このページは復元試験
済み、稼働中のアトミックなスナップショット、保存後の書き込みの復旧を
保証しません。Parquet ファイルやカタログを新版のディレクトリに個別に
混ぜないでください。ヘルスが正常なだけで元のボリュームを消さないでください。

保存形式のバージョン管理とリスナー起動前の拒否は別件の issue #200 です。
このガイドはその機能を実装しません。
