# Authentication

sigiro uses **prefixed API keys** for authentication. Every request to the query/investigate API requires a valid key. OTLP ingest also requires a key.

## Key format

Keys follow the format `sigiro_<8-char-short>_<24-char-long>`, verified via SHA-256 hash lookup.

| Prefix | Mode | Behavior |
|--------|------|----------|
| `sigiro_dev_` | Local development | Bypass — no DB lookup, returns `dev_project` context |
| `sigiro_` | Production | Verified against admin DuckDB |

## Quick start (local dev)

No setup needed. Any token starting with `sigiro_dev_` works:

```bash
curl -s http://localhost:9999/v1/services \
  -H "Authorization: Bearer sigiro_dev_anything"
```

All data lands in a single `dev_project` namespace. Use this for local testing only.

## Create production keys

```bash
# Server must be running
curl -s -X POST http://localhost:9999/admin/keys \
  -H "Content-Type: application/json" \
  -d '{"project": "my_app", "plan": "free"}'
# → {"key":"sigiro_BRTRKFsL_..."}
```

Supported plans: `free` (default), `builder`, `pro`, `team`. Rate limit defaults to 100 req/s.

### Via CLI

```bash
cargo run -- admin create-key --project my_app --plan free
cargo run -- admin revoke-key BRTRKFsL
```

## Save your key

```bash
cargo run -- auth sigiro_BRTRKFsL_...
# Saved to ~/.config/sigiro/config.toml (permissions: 0600)
```

### Key resolution order

1. `SIGIRO_API_KEY` environment variable (CI/CD, Docker)
2. `~/.config/sigiro/config.toml` (saved via `sigiro auth`)

```toml
# ~/.config/sigiro/config.toml
api_key = "sigiro_BRTRKFsL_..."
```

## Auth caching

Successful verifications are cached for 60 seconds. Failed verifications are **not** cached. This means key revocation takes up to 60s to take effect for active clients.

## Where auth is required

| Endpoint | Auth required |
|----------|--------------|
| `GET /health` | No |
| `POST /v1/query` | Yes — Bearer token |
| `POST /v1/investigate` | Yes — Bearer token |
| `GET /v1/services` | Yes — Bearer token |
| `POST /v1/traces` (OTLP) | Yes — Bearer token |
| `POST /v1/logs` (OTLP) | Yes — Bearer token |
| `POST /v1/metrics` (OTLP) | Yes — Bearer token |
| `POST /v1/profiles` (OTLP) | Yes — Bearer token |
| `POST /admin/keys` | No (internal) |
| `DELETE /admin/keys/{token}` | No (internal) |

## Multi-tenant isolation

Each API key maps to a `project_id`. Each project gets its own DuckLake catalog at `~/.sigiro/data/{project_id}/catalog.ducklake`. Keys from different projects cannot access each other's data.

## Rate limiting

API endpoints are rate-limited at 2 req/s per Bearer token, burst 10 (GCRA algorithm). OTLP ingest endpoints are not rate-limited.
